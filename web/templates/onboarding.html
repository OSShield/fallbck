What should this agent back up?

Files
Filesystem agent for Linux and Windows hosts. Directories and volumes are archived to Proxmox Backup Server as pxar snapshots with metadata change detection.
Database
Database agent: the same fallbck-agent with the vendor client tools installed. Dumps PostgreSQL, MySQL/MariaDB and MongoDB and records WAL, binlog and oplog positions for point-in-time restores.
Kubernetes
In-cluster agent installed with Helm. Backs up all API resources, persistent volumes (CSI snapshots or live mounts) and databases running inside the cluster.
Proxmox VE host
Filesystem agent on a Proxmox VE node. Archives the node configuration (/etc/pve, packages, storage, network, disk layout) for disaster recovery. Guest disks stay with vzdump.
Docker host
Filesystem agent on a Docker host, as a package or as a container with the socket mounted. Archives container, network and volume definitions, compose files and every named volume.

Where will the agent run?

Debian / Ubuntu
apt package from deb.pkg.lv, managed by systemd.
RHEL / Rocky / Alma / Fedora
rpm package from rpm.pkg.lv, managed by systemd.
Alpine Linux
apk package from alpine.pkg.lv, managed by OpenRC.
Other Linux
Static binary from the GitHub release with a hand-installed systemd or OpenRC service.
Windows
MSI installer from the GitHub release, runs as a Windows service with Volume Shadow Copies.
Kubernetes cluster
Helm chart from oci.fi installed into the fallbck namespace of the target cluster.
Docker container
The agent container image (compose snippet): as root with the Docker socket mounted for Docker host backups, or the tools flavour for databases reachable over the network.
Proxmox VE node
Debian-based: the apt package from deb.pkg.lv installed as root on the node.
What happens during enrollment:
  1. The agent contacts the server and validates the single-use token.
  2. The server provisions a dedicated task queue and issues the agent's bearer token.
  3. The agent starts its worker and reports its capabilities with the first heartbeat.

What should the agent back up?

Files
Directories or whole volumes, archived file by file with change detection.
Database
PostgreSQL, MySQL/MariaDB or MongoDB dumps with WAL, binlog or oplog positions.
Proxmox VE host
Node configuration, package lists, storage and network definitions, optional data paths.
Docker host
Container, network and volume definitions, compose files, named volumes and extra host paths.
Kubernetes cluster
All API resources plus persistent volumes, one snapshot group per PVC.
