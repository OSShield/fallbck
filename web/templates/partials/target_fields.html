The key lives on a key ring, generated and kept on the server (sealed with its master key) and handed to agents per run. Export the key file after saving: without it, or the server database plus master key, the backups cannot be restored.
Targets on one ring share the key, so namespaces of the same datastore deduplicate against each other. Separate rings keep targets isolated. Switching an encrypted target to another ring starts a new chunk history.
Each snapshot then also carries the encryption key wrapped with this key, so the private key can recover the data if the key file is lost (proxmox-backup-client key import-with-master-key).
Rotate or import a key
Both act on the key ring, so every target on it is affected. Rotation starts a new chunk history (nothing deduplicates against the old key) and keeps the old key for the snapshots written with it. Import adopts a key from another ring or proxmox-backup-client.
